# ns8-grist

A [NethServer 8](https://github.com/NethServer/ns8-core) module for [Grist](https://www.getgrist.com/), the relational spreadsheet that combines the flexibility of a spreadsheet with the robustness of a database.

The module runs the upstream `gristlabs/grist` image in a rootless Podman container. Grist keeps its home database (SQLite), documents and attachments in the `grist-data` Podman volume.

## Install

Instantiate the module with:

```bash
add-module ghcr.io/geniusdynamics/grist:latest 1
```

The output will return the instance name:

```json
{
  "module_id": "grist1",
  "image_name": "grist",
  "image_url": "ghcr.io/geniusdynamics/grist:latest"
}
```

## Configure

Let's assume that the grist instance is named `grist1`.

Launch `configure-module`, by setting the following parameters:

- `host`: a fully qualified domain name for the application
- `http2https`: enable or disable HTTP to HTTPS redirection (true/false)
- `lets_encrypt`: enable or disable Let's Encrypt certificate (true/false)
- `default_email`: email of the Grist administrator. The user who logs in with this address becomes the installation administrator and owns the first team site
- `single_org`: (optional) name of the single team site served at the root of the host, lowercase letters, digits and hyphens. If empty, Grist serves multiple team sites under `/o/<name>`

Example:

```bash
api-cli run configure-module --agent module/grist1 --data - <<EOF
{
  "host": "grist.example.org",
  "http2https": true,
  "lets_encrypt": false,
  "default_email": "admin@example.org",
  "single_org": "grist"
}
EOF
```

The above command will:

- start and configure the grist instance
- configure a virtual host for Traefik to access the web UI

The public URL (`APP_HOME_URL`) is derived from `host`: `https://<host>` when HTTPS redirection or Let's Encrypt is enabled, `http://<host>` otherwise.

Grist has no local passwords: users sign in through Grist's login page, and the administrator is the user who signs in with `default_email`. For single sign-on, see the upstream [self-managed documentation](https://support.getgrist.com/self-managed/).

### Ports

Grist listens on port 8484 in the container. It is published on `127.0.0.1` only, on the TCP port reserved for the module (`TCP_PORT`, see `runagent -m grist1 env`), and exposed by Traefik at `https://<host>/`.

### Secrets

The secret used to sign session cookies (`GRIST_SESSION_SECRET`) is generated by `add-module` and stored in `state/passwords.env` (mode 0600, included in the module backup):

```bash
runagent -m grist1 sh -c 'ls -l "$HOME/.config/state/passwords.env"'
```

Settings that are not secret are stored in the module environment.

## Get the configuration

You can retrieve the configuration with

```bash
api-cli run get-configuration --agent module/grist1
```

## Backup and restore

The backup includes `state/passwords.env` and the `grist-data` volume, which holds the home database, the documents and the attachments. Grist uses SQLite files, so no database dump is made: take backups when the instance is idle if you need a guaranteed consistent copy of busy documents.

On restore, the settings are restored from the module environment and `configure-module` is called again with all of them. A cloned module starts with an empty data volume and its own session secret.

## Update

Update your instance

```bash
api-cli run update-module --data '{"module_url":"ghcr.io/geniusdynamics/grist:latest","instances":["grist1"],"force":true}'
```

## Uninstall

To uninstall the instance:

```bash
remove-module --no-preserve grist1
```

## Debug

### Check Environment Variables

The module runs under an agent that initializes environment variables in `/home/grist1/.config/state`. To verify them:

```bash
runagent -m grist1 env
```

### Access the Module Environment

Become the runagent for testing scripts with all environment variables loaded:

```bash
runagent -m grist1
```

### Container Debugging

First, enter the module environment:

```bash
runagent -m grist1
```

List running containers:

```bash
podman ps
```

Show the Grist logs:

```bash
podman logs grist
```

The service logs are available with `journalctl` as well:

```bash
runagent -m grist1 journalctl --user -u grist.service
```

The application health check is `/status`, it answers with HTTP 200 once Grist is ready.

## Testing

This module uses the NS8 standard testing infrastructure: the `Test module` workflow runs the [Robot Framework](https://robotframework.org/) suite in `tests/` on a QEMU NS8 cluster, after the `Publish images` workflow has built the module images. To run the suite locally, refer to the [Running tests locally](https://github.com/NethServer/ns8-github-actions/blob/v1/README.md#running-tests-locally) section of the ns8-github-actions README.

## Updating Grist

Grist is pulled from `docker.io/gristlabs/grist`, pinned in the `org.nethserver.images` label set by `build-images.sh` (currently `1.7.22`). Bump the `grist_image` variable there, read the upstream [release notes](https://github.com/gristlabs/grist-core/releases), then run the test workflow.
